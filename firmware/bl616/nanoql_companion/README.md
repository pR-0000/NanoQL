# NanoQL unified BL616 firmware

This source module extends the pinned FPGA Companion firmware with a safe USB role choice:

- S1 left untouched: autonomous Companion mode with USB keyboard and microSD;
- S1 pressed after the FPGA LEDs start, including while QDOS runs: NanoQL Link USB CDC development mode without resetting the FPGA.

S1 is also the Gowin MODE0 configuration pin and must not be held while the board is powered on. Press it only after the FPGA LEDs or HDMI output appear. The FPGA latches S1 and exposes it through the standard `SPI_SYS_BUTTONS` command. S2 is not used by NanoQL Link. If the FPGA cannot boot, the firmware automatically exposes NanoQL Link as a recovery path so a damaged configuration Flash can be repaired without changing BL616 firmware. Switching to CDC disconnects the USB-host keyboard; the remote keyboard can then take over. The Companion task remains active at a lower priority so the microSD, mounted QL-SD images, and OSD continue to operate in development mode. NanoQL Link can also replace `MDV1.mdv`, mount it in slot 2 for the current session, and reset only the QL. FPGA SPI transactions are serialized by the BL616 mutex.

In autonomous mode, `nanoql_drive.c` converts a selected folder below `/NanoQL/Microdrives` into an exact 174,930-byte QLAY image. It accepts up to 126 files, eight nested directory levels, flattened printable-ASCII names up to 36 characters, and at most 253 allocated 512-byte sectors. It writes `/NanoQL/Generated/<folder>.mdv` through an atomic temporary-file replacement, mounts that named image read/write for the current session, and resets only the QL after the menu command completes. QDOS writes update the generated cartridge rather than the source folder. Generated images are excluded from normal INI persistence. The source patch and generated board images are distributed under the upstream Apache License 2.0.

Overlay settings are also saved atomically from a dedicated low-priority task, so slow microSD synchronization cannot block menu input. Repeated changes are coalesced while a write is active. The firmware writes and synchronizes `nanoql.ini.tmp`, keeps the previous complete configuration as `nanoql.ini.bak` during replacement, and restores that backup automatically if a power interruption leaves the primary INI file missing. Selecting a keyboard layout or another persistent option therefore cannot truncate the active ROM configuration.

NanoQL Link is a USB CDC device, not the official FPGA Partner firmware's dual-channel `SIPEED USB Debugger`. It streams bitstreams directly from USB to the BL616 JTAG engine through the NanoQL Python tool, without using the microSD, but does not enumerate as the A/B interface expected by Gowin Programmer. The `fpga` command targets volatile SRAM.

The validated GW2AR-18 persistent writer uses the same SPI-over-JTAG configuration path as external FPGA tools. After NanoQL starts, briefly press S1 once, then run `python tools/nanoql_link.py --port PORT fpga-flash path/to/extracted-release-folder --yes`. Both the host tool and BL616 verify the Gowin preamble and GW2AR-18 device identifier before the first Flash block can be erased, so a BL616 firmware file cannot be written as an FPGA bitstream. The writer identifies configuration Flash, erases the required 64 KiB blocks, programs and verifies the bitstream, then restarts the board. The optional `fpga-flash-probe` command only checks the JEDEC identifier and write-enable behavior. Do not disconnect power or USB during programming. S2 is not used. Restoring the official BL616 profile and using `fpga-flash-native` remains the external-JTAG recovery method.
